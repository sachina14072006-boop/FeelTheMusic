FeelTheMusic Deployment Guide
=============================

This guide documents what was changed, how the project was deployed, where each service is hosted, and how to maintain or redeploy the application.


1. Project Summary
------------------

FeelTheMusic is a full-stack music recommendation application with these parts:

- React/Vite frontend in the client/ folder
- Node.js/Express backend in the server/ folder
- MySQL database using database/schema.sql and database/seed.sql
- Python/FastAPI emotion detection service in the emotion-service/ folder

7. Railway Deployment Steps Used
--------------------------------

Step 1: Logged in to Railway CLI.

Command:
railway login

Step 2: Created a Railway project.

Command:
railway init -n FeelTheMusic --json

Created Railway project:
FeelTheMusic

Step 3: Added Railway MySQL.

Command:
railway add --database mysql --json

Created service:
MySQL

Step 4: Added backend service.

Command:
railway add --service feelthemusic-backend --json

Created service:
feelthemusic-backend

Step 5: Added emotion service.

Command:
railway add --service feelthemusic-emotion --json

Created service:
feelthemusic-emotion

Step 6: Set backend environment variables.

Command pattern:
railway variable set DB_HOST=<host> DB_USER=<user> DB_PASSWORD=<password> DB_NAME=<database> JWT_SECRET=<secret> --service feelthemusic-backend --skip-deploys

Step 7: Deployed backend from the server/ folder.

Command:
railway up server --service feelthemusic-backend --path-as-root --detach --message "Deploy FeelTheMusic backend"

Step 8: Generated backend public domain.

Command:
railway domain --service feelthemusic-backend --port 5000 --json

Generated backend URL:
https://feelthemusic-backend-production.up.railway.app

Step 9: Applied database schema and seed data to Railway MySQL.

The installed MySQL CLI on the machine was too old for Railway MySQL authentication, so the schema was applied using the Node.js mysql2 driver from the server dependencies.

Command pattern used:
node -e "const fs=require('fs'); const mysql=require('mysql2/promise'); (async()=>{const c=await mysql.createConnection({host:'<public-host>',port:<public-port>,user:'root',password:'<password>',database:'railway',multipleStatements:true}); await c.query(fs.readFileSync('../database/schema.sql','utf8')); await c.query(fs.readFileSync('../database/seed.sql','utf8')); await c.end(); console.log('Railway schema and seed applied');})().catch(e=>{console.error(e.message); process.exit(1);});"

Step 10: Set emotion service start command.

Command:
railway variable set "NIXPACKS_START_CMD=uvicorn main:app --host 0.0.0.0 --port $PORT" --service feelthemusic-emotion --skip-deploys

Later, this was replaced effectively by using a Dockerfile.

Step 11: Deployed emotion service from the emotion-service/ folder.

Initial command:
railway up emotion-service --service feelthemusic-emotion --path-as-root --detach --message "Deploy FeelTheMusic emotion service"

Step 12: Fixed emotion service crash.

Problem:
The first emotion service deployment crashed with this error:
ImportError: libxcb.so.1: cannot open shared object file: No such file or directory

Cause:
OpenCV needed Linux runtime libraries that were missing from Railway's default Python image.

Fix:
Created emotion-service/Dockerfile and installed:
- libgl1
- libglib2.0-0
- libsm6
- libxext6
- libxcb1

Redeploy command:
railway up emotion-service --service feelthemusic-emotion --path-as-root --detach --message "Fix emotion service runtime libraries"

Step 13: Generated emotion service public domain.

Command:
railway domain --service feelthemusic-emotion --port 8000 --json

Generated emotion service URL:
https://feelthemusic-emotion-production.up.railway.app

12. How to Update Database Again
--------------------------------

If schema.sql or seed.sql changes, apply them to Railway MySQL again.

Recommended approach:
Use the Node.js mysql2 driver from the server folder because older local MySQL CLI versions may fail against Railway MySQL.

Command pattern:

cd server
node -e "const fs=require('fs'); const mysql=require('mysql2/promise'); (async()=>{const c=await mysql.createConnection({host:'<public-host>',port:<public-port>,user:'root',password:'<password>',database:'railway',multipleStatements:true}); await c.query(fs.readFileSync('../database/schema.sql','utf8')); await c.query(fs.readFileSync('../database/seed.sql','utf8')); await c.end(); console.log('Schema and seed applied');})().catch(e=>{console.error(e.message); process.exit(1);});"


13. Common Troubleshooting
--------------------------

Problem:
Registration fails.

Likely cause:
Backend cannot find the users table or database variables are wrong.

Check:
- Railway backend variables
- Railway MySQL status
- database/schema.sql applied successfully


Problem:
Frontend loads but API calls fail.

Likely cause:
VITE_API_URL was missing or pointed to localhost during production build.

Fix:
Redeploy frontend with:
VITE_API_URL=https://feelthemusic-backend-production.up.railway.app/api


Problem:
Webcam emotion detection fails.

Likely causes:
- Browser camera permission denied
- Emotion service is down
- VITE_EMOTION_API_URL is wrong
- DeepFace model download/startup is slow on first request

Check:
https://feelthemusic-emotion-production.up.railway.app/


Problem:
Emotion service returns 502.

Likely cause:
The Python app crashed.

Check logs:
railway logs --service feelthemusic-emotion --deployment

Known fix already applied:
The Dockerfile installs OpenCV runtime libraries, including libxcb1.
